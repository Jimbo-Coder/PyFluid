# Mac CPU performance baseline: 2026-10-01

This baseline records the current AMReX production source state and AMReX 26.10 (`015c14b65715b277fbc54706ebe7455b196d2254`). The baseline commit containing this file checkpoints the accumulated AMReX/WSL/CUDA work; validation here is scoped to Mac CPU and the separately stated Metal controls.

## Measurement contract

Apple M4, 10 CPU cores, 16 GiB memory, macOS 27.0.1, Apple Clang 21.0.0. CPU FP64, Release/native tuning, three MPI ranks with binding disabled, and the same production methods and case inputs. The comparison uses identical solver source against exact AMReX 26.09 and 26.10 installs. Runs are ordered old/new/new/old, each pass with three repeats: six samples per release/case. No task compilation overlaps the timing passes. Each repeat passes the existing scalar checks.

The canonical values in `../tools/benchmark_pyfluid.py` are medians of the six 26.10 samples. The existing 0.85 performance warning fraction and all numerical thresholds remain unchanged. The prior canonical references (109.9095765, 61.3922574, 2.59827142, 2.030347723 Mcells/s) were measured on older source states; all four still passed those limits before this refresh.

These are local case measurements, not a universal speedup. WENO-Z improves, RMHD is slightly slower, and cheap hydro changes by about half a percent. The recovery microbenchmark retains identical success/failure counts, iterations, residuals and checksums; changed Clang finite-predicate machinery is a possible overhead source, not a proven sole cause. No NaN protection or arithmetic policy was weakened.

## Accuracy and acceptance scope

All 265 matched Sod exact-profile/integral, Brio-Wu AMR+CT/rotation/ratio-four, and explicit/implicit diffusion metrics are identical between releases. The 13 selected standard gates pass: architecture, exact reference sampling, RHD, reference-metric RHD, RMHD, fixed spacetime, dimensional consistency, rank reproducibility, codegen contract, Sod, gravity, Brio-Wu reference and diffusion amplitude. Cycle456 additionally verifies exact subcycling restart and focused elliptic/implicit/ratio-four controls.

The complete standard suite remains red at the pre-existing `hydro_self_gravity_amr_subcycling` case: total-energy drift 2.243662e-6 exceeds 2e-6 on both releases, matching earlier continuity cycles. The other 17 standard feature cases pass. This baseline preserves that failure and does not certify the full suite or all current GPU/GR/stellar combinations.

## Optional upstream features

A warmed Metal FP32 cell-centered Helmholtz probe compares synchronization modes in both orders with unchanged analytic-discrete error checks. Small 32/64-cell problems with one or sixteen boxes are about 7.7--9.3 times faster using `MLMG::setNoGpuSync(true)`, with identical error, mean error and residual. This establishes a useful integration candidate, not a production-wide switch: actual diffusion/gravity/nodal/edge operators and larger box counts still need on/off acceptance. No production synchronization policy changed.

Sparse AMG/Krylov is available for future irregular matrix operators; current structured MLMG paths do not justify new matrix assembly/integration. Whole-direction refinement and unsplit-grid options are relevant to slab/anisotropic layouts, but do not change the selected interpolater or automatically extend state/CT refinement-ratio support.
