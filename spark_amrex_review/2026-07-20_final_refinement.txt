Priority 1 (high confidence, potential behavior/robustness impact)

- pyfluid_amrex/src/amr/amr_solver_auxiliary.cpp:66
  - `should_refresh_mhd_aux_fields(int step, bool write_aux_gfs)` accepts `write_aux_gfs` but ignores it.
  - Impact: dead API surface (and missed intent signal) can cause unnecessary recompute on non-aux-output steps or hide a future scheduling regression.
  - Suggestion: either remove the parameter and simplify callers, or gate refresh logic with it so output cadence and compute cadence stay in one decision path.

- pyfluid_amrex/src/amr/output.hpp:34-102
  - `append_plotfile_metadata_on_io_rank` returns silently when fallback `.meta` file cannot be opened.
  - Impact: missing plotfile metadata can silently disappear without diagnostics, reducing reproducibility and traceability in HDF5 fallback mode.
  - Suggestion: emit a hard/fatal warning when both HDF5 metadata and `.meta` append fail (or at least log including `plotfile_stem`, format, step, and time).

- pyfluid_amrex/src/amr/amr_solver_multipatch.cpp:12-26
  - `configured_patch_counts()` treats any one non-zero axis as “configured” and copies all axes directly.
  - Impact: partial `mesh_patch_counts` input can pass parser checks then fail with generic non-positive/even-divide aborts later.
  - Suggestion: enforce all-or-none policy at parse/validation stage (all dims set or all zero), with clear message listing missing axes.
